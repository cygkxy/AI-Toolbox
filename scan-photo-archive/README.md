# 扫码拍照存档 (scan-photo-archive)

一个跑在浏览器里的「扫设备二维码 → 拍照 → 存档」小工具。没有后端、没有数据库,
照片直接落到你指定的文件夹(桌面端)或系统下载目录/相册(手机端)。

面向的场景:仓库/机房/产线上有一堆设备,每台贴一个二维码,需要逐台拍照留档并按设备号命名。

## 特点

- **一次只扫一个**:识别成功自动停止扫描,给这台设备想拍几张拍几张
- **设备清单**:本次录入的设备号 + 已拍张数一览,点任意一行即可切过去补拍
- **不覆盖**:按「最大编号 + 1」命名,删过中间文件也不会覆盖已有照片
- **按文件夹校准**(桌面端):选好保存文件夹后,以文件夹里的**真实文件**为准统计张数,
  删了照片点一下校准数字就跟着降
- **纯前端**:只需要一个静态文件服务器,拍的照片不经任何服务器
- 二维码识别用 [jsQR](https://github.com/cozmo/jsQR),已本地化,不依赖 CDN

## 目录结构

```
AI-Toolbox/scan-photo-archive/     ← 就是你进来的这个目录
├── serve.js              # 静态服务器: 8000 混合 http/https, 8080 http, 8443 https
├── webroot/
│   ├── index.html        # 全部逻辑都在这一个文件里
│   └── jsQR.js           # 二维码解码库(vendored)
└── deploy/
    └── scan-web.service  # systemd 单元示例(里面的路径要按你的部署位置改)
```

## 快速开始

### 1. 生成自签证书

摄像头 API 只在**安全上下文**(HTTPS 或 localhost)下可用,所以公网访问必须走 HTTPS。
自签证书就够用(浏览器点一次「继续前往」即可)。

```bash
openssl req -x509 -newkey rsa:2048 -nodes -days 825 \
  -keyout key.pem -out cert.pem \
  -subj "/CN=your-host" \
  -addext "subjectAltName=IP:你的公网IP,IP:内网IP,DNS:localhost"
```

> 有正式域名的话,把 `cert.pem` / `key.pem` 换成 Let's Encrypt 签发的即可,就没有警告了。

### 2. 启动

```bash
node serve.js
```

| 端口 | 协议 | 用途 |
|---|---|---|
| 8000 | **HTTP + HTTPS 混合** | 靠首字节 `0x16 0x03` 自动识别是不是 TLS 握手,两种写法都能开 |
| 8080 | 纯 HTTP | 备用 |
| 8443 | 纯 HTTPS | 备用 |

混合端口是刻意做的:很多路由器只肯转发一个端口,这样 HTTPS 也能复用同一个口。

### 3. 访问

```
https://<你的地址>:8000/
```

首次会提示证书不受信任 → 高级 → 继续前往。跳过警告后浏览器仍把它当安全上下文,
摄像头可以正常调用。

### 4. 装成 systemd 服务(可选)

```bash
# 先按你的实际路径改一下单元里的 WorkingDirectory / ExecStart
sudo cp deploy/scan-web.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now scan-web
journalctl -u scan-web -f
```

## 使用流程

```
点「开始扫描」→ 扫一个二维码 → 自动停下
                                  ↓
                        给这台设备拍照(拍几张存几张)
                                  ↓
                    点「扫下一个设备」→ 扫下一个码 → …
```

- 清单里点任意一行 = 切到该设备(会自动暂停扫描,方便从容补拍)
- 每行右侧的「**重置**」把该设备计数归零,下一个文件从 `_001` 重新开始
- 桌面端选过保存文件夹后,面板上会出现「**按文件夹校准**」
- 快捷键:空格 = 拍照;预览中空格 = 保存

## 文件命名

```
<设备号>_<三位序号>.jpg
例: DEV-001_001.jpg  DEV-001_002.jpg  DEV-002_001.jpg
```

设备号由二维码内容清洗而来(`\ / : * ? " < > |` 和控制字符换成 `_`,空白换成 `_`,截断到 64 字符),
照片左下角会烧入两行水印:

```
SN：DEV-001
日期：2026-10-16 11:30:45
```

日期是**按下快门那一刻的本地时间**,格式 `YYYY-MM-DD HH:mm:ss`。

每台设备**独立编号**,序号存在浏览器 localStorage 里。

### 关于「已拍 N 张」

这个数字有两个来源:

| 场景 | 计数来源 | 说明 |
|---|---|---|
| 手机端(没选文件夹) | localStorage 计数器 | 记的是「拍过几张」,**删本地照片不会自动变**,点「重置」归零 |
| 桌面端(选了文件夹) | 文件夹里的真实文件 | 删了照片点「按文件夹校准」即同步 |

## 浏览器要求

- 需要 HTTPS 或 localhost,否则 `getUserMedia` 被拒
- 桌面端的「选择保存文件夹」依赖 File System Access API(Chrome / Edge)
- 手机浏览器无法写指定文件夹,保存走系统下载/相册;此时「选择保存文件夹」按钮不会出现

## 隐私

照片全程只在浏览器内存里处理,不经过任何服务器;`serve.js` 只负责发静态文件。
